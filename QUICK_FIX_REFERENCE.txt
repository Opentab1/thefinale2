PROBLEM: db_reader and song_detector stop after ~6 minutes

ROOT CAUSE: Event loop thread leak
  → _ensure_event_loop() called every 5 seconds
  → Each call created new thread without stopping old one
  → After ~72 iterations (6 min): too many threads → crash

7 CRITICAL FIXES APPLIED:

1. ✅ Removed event loop recreation from detection loop
   → Event loop now created once and reused forever
   → No more thread accumulation

2. ✅ Fixed race condition in thread restart
   → Old thread properly terminated before new one starts
   → No more multiple threads running simultaneously

3. ✅ Added event loop thread monitoring to watchdog
   → Watchdog now checks event loop thread health
   → Automatic recovery if event loop dies

4. ✅ Enhanced event loop cleanup
   → Proper thread termination with timeouts
   → No lingering threads after restart

5. ✅ Made event loop creation non-critical
   → System starts even if event loop creation fails initially
   → Will retry on-demand

6. ✅ Fixed hub health monitoring
   → Checks timestamps not values (no false positives)
   → More accurate failure detection

7. ✅ Added database error handling
   → Main loop can't crash from DB errors
   → Automatic recovery after multiple errors
